Design proposal · 19 Sep 2026

Redesigning Macarchy Settings

The plumbing works — every value in the window is read back from the running stack. What's let it down is the presentation layer: one row shape doing seven jobs, a stock sidebar, and a grouped Form that leaves half the window empty. Below: what's wrong, what macOS 26 changed, and eight concrete replacements.

Diagnosis

Nine things the current window gets wrong

Read off the Advanced screenshot and the code behind it — RootView.swift, AdvancedPane.swift, and the four editing panes.

01

The window is mostly gutter

.formStyle(.grouped) caps and centres the content column. In a 1000pt window that leaves roughly 200pt of nothing on each side — and the panes with live previews are exactly the ones that could use the space.

02

One row shape does seven jobs

Daemons, generated files, workarounds, snapshots, toggles and sliders are all LabeledContent with a title, a 10pt monospace second line and trailing controls. Nothing reads as more or less important than anything else.

03

A wall of grey pills

Advanced shows Restart + Stop × 4, Regenerate × 3 and Restore × 20. Roughly thirty buttons at identical weight, most of which you press once a month.

04

Five visual languages for one idea: state

running · 33881, active, up to date, ✓ generated, not yet generated — same concept, five treatments, three fonts.

05

The sidebar is stock

A plain List with a full-width solid blue selection slab — the pre-Tahoe look. No search, no per-item state, no identity, and the daemon footer is 10pt grey text rather than something you'd trust at a glance.

06

Previews scroll away when you use them

BorderPreview, TilingPreview and MenuBarStrip live in a Section("Preview") at the top of the scroll view. Reach the slider and the thing it previews is off-screen.

07

Sliders never got their number field

PLAN.md promised "slider + numeric field side by side — drag for feel, type for precision". What shipped is a fixed 160pt track and a read-only label. No typed entry, no units, no tick marks.

08

Advanced is four apps in a trench coat

Process control, workaround tracking, file generation and a 20-deep snapshot history share one scroll. The snapshot list alone pushes everything else off screen.

09

Rationale is shipping as UI text

"Surfaced here so a stopgap cannot quietly become permanent." Good writing — but four-line grey footers under every section make the pane read like a README with controls embedded in it.

Research

What macOS 26 actually changed

The app is running on macOS 27 and still looks like a Ventura settings window. The Tahoe design pass is mostly free if you build against the new SDK, but four of its ideas need deliberate adoption:

  • The sidebar floats on glass. Sidebars sit on a Liquid Glass surface above content and tint subtly from what's beneath them. Detail panes want .scrollContentBackground(.hidden) so the material shows through, and the scroll edge effect replaces hard divider lines.
  • Colour means something now. Toolbar and control icons render monochrome by default; tint is reserved for meaning. Seven blue SF Symbols in a sidebar is exactly the decoration the new system removes.
  • Controls grew up. Buttons are capsules with more height; sliders draw tick marks automatically when given a step, and support a neutral centre value — which is precisely what the menu bar's −20…20 vertical offset wants.
  • Toolbars group explicitly. ToolbarSpacer(.fixed) / (.flexible) separate action clusters, and .glassProminent marks the one action in a pane that matters. Pane actions belong up there, not scattered through the form.
  • Glass chrome needs a real window. SwiftUI's Window scene doesn't expose the style mask, so the full-size content view and glass title bar need an NSWindowController with .fullSizeContentView and a real NSToolbar.

Proposal 01

High impact~half a day

A sidebar that carries state

The sidebar is the first thing you see and currently the least informative surface in the app. Replace the stock list with: tinted icon tiles on a glass ground, a capsule selection instead of the full-width blue slab, a trailing value on rows that have live state, a search field, and a health card at the bottom that's a button, not a caption.

// Pane gains its own tint + a live trailing value.
var tint: Color { switch self { case .themes: .purple; case .borders: .teal; … } }

Label { Text(pane.title) } icon: {
    Image(systemName: pane.symbol)
        .foregroundStyle(isSelected ? .white : pane.tint)
        .frame(width: 19, height: 19)
        .background(pane.tint.opacity(isSelected ? 1 : 0.16),
                    in: .rect(cornerRadius: 5))
}
.badge(model.trailingValue(for: pane))   // "midnight", "bsp", "9"

Proposal 02

Highest impact~1–2 days

Three row types instead of one

This is the fix for "the editing sections look awful". Right now every row is LabeledContent, so a daemon you can kill looks identical to a checkbox. Define three components and use nothing else.

// One control row, used by every editing pane.
struct ControlRow<Control: View>: View {
    let title: String
    var help: String? = nil
    @ViewBuilder var control: Control

    var body: some View {
        LabeledContent {
            control.frame(maxWidth: 260, alignment: .trailing)
        } label: {
            VStack(alignment: .leading, spacing: 1) {
                Text(title)
                if let help { Text(help).font(.caption).foregroundStyle(.secondary) }
            }
        }
    }
}

// Slider + typed field + unit, the pairing PLAN.md specified.
ValueSlider(value: $layout.windowGap, in: 0...32, step: 1, unit: "px")

Proposal 03

High impact~1 day

Give the empty gutters a job: a preview rail

Every geometry pane has a live preview stuck at the top of a scroll view, where it disappears the moment you touch the control it's previewing. Move it into an .inspector() rail that stays put. The wasted width becomes the most useful part of the window, and the form column gets to keep its comfortable measure.

NavigationSplitView { Sidebar() } detail: {
    LayoutForm()
        .inspector(isPresented: $showPreview) {
            LayoutPreviewRail()
                .inspectorColumnWidth(min: 190, ideal: 220, max: 280)
        }
        .toolbar { ToolbarItem { Button("Preview", systemImage: "sidebar.right") { showPreview.toggle() } } }
}

Proposal 04

Medium impact~2 hours

Pane headers and a real toolbar

Each pane currently has a navigationTitle and nothing else, while its actions — Refresh, Import…, Reload SketchyBar, Open config — sit as loose buttons wherever they landed in the form. Promote them. Every pane gets a two-line header stating where its values come from (the app's most trustworthy quality, currently only mentioned in footer prose) and a toolbar with one prominent action.

  • Themes — "8 installed · applied via theme-switch" · toolbar: Import…, Apply (prominent)
  • Borders — "No query API · values from settings.env" · toolbar: Reset corners
  • Menu Bar — "sketchybar --query bar" · toolbar: Open config, Reload (prominent)
  • Layout — "yabai -m config" · toolbar: Preview toggle
  • Advanced — "4 daemons · 2 workarounds · 20 snapshots" · toolbar: Refresh, History…

Proposal 05

High impact~1 day

Advanced becomes a status dashboard

Four unrelated concerns share one scroll, and the snapshot list buries the rest. Restructure: daemons become a 4-up tile grid you can read in one glance, workarounds become a dated callout that can expire, generated files keep their rows, and snapshots move behind a History… sheet where 20 entries don't cost anything.

Proposal 06

Medium impact~1 hour

One vocabulary for state

Five treatments collapse into one StatusPill with four semantic cases. Colour carries meaning only — which is also what the Tahoe guidance asks for — and the wording becomes consistent: present tense, capitalised, no monospace.

Proposal 07

Medium impact~2 hours

The console earns the bottom of the window

The command log is the most distinctive thing in this app — it's the receipt for every value you change — and it's currently a 9pt grey label trapped under the detail column. Span it across the full window, give it a severity dot, a count, and a timestamp, and keep the history sheet.

Proposal 08

Medium impact~half a day

Themes: stop the page from jumping

Selecting a theme currently appends four sections below the grid, so the visible result of a click is… nothing, until you scroll. Put the grid in the content column and the editor in the same inspector rail from Proposal 03: selection updates the rail instantly, the grid never moves, and the terminal preview sits beside the colours it's made of rather than above them.

  • Swatch-first colour rows — well on the left, editable hex field on the right, so you can paste 0xff66CCFF instead of hunting in the colour picker.
  • Apply as the prominent toolbar action, not a button in the sixth section. Double-click-to-apply stays, but stops being the only discoverable path.
  • "Edited" becomes a real diff affordance — the pill opens a popover of which keys differ from the shipped default, with Reset per key.
