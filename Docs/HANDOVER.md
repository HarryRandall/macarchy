# Handover

For whoever picks this up next. Read this before touching anything.

## What this project is

A native macOS app (`~/projects/macarchy-settings`) that is taking over
configuration of Harry's desktop stack — **yabai, JankyBorders, SketchyBar,
skhd** — from a pile of shell scripts, chiefly a 995-line `theme-switch`.

This is his **daily driver machine**. It is not a sandbox. Breaking the desktop
means breaking the machine he is working on.

## The five rules

Break any of these and you will break the desktop in a way that is hard to see.

**1. Read live from the daemons; persist to env files; never parse an rc script.**
yabai and sketchybar both answer queries, so the UI hydrates from what is
actually running. borders has no query verb — `settings.env` is authoritative
for it alone.

**2. Strangler, never dual ownership.** Build the new path, run it beside the old
one, diff, cut over, *then delete the old path*. Two things writing one file is
the failure mode this project keeps hitting. It does not announce itself: a
`theme-switch` function silently reverted a completed migration an hour later,
between checks.

**3. There are two entry points for theme switching.** The GUI, and
`cmd+ctrl+=` bound to `theme-switch` in `skhdrc:130`. A surface ported into the
app alone makes them disagree. Ported logic goes in **`Sources/MacarchyKit`**,
which the app and the `macarchy` CLI both depend on, and `theme-switch` calls
the CLI. One implementation, whichever way a theme is applied.

**4. The GUI is never in the boot path.** Generated rc files still resolve
`settings.env` and the active theme *at run time*. The desktop must configure
correctly at login whether or not the app ever starts.

**5. `doctor` is the gate.** Run `./Scripts/doctor.sh` before and after every
change. A change that leaves it failing gets reverted, not patched forward. When
you hit a new failure mode, add an assertion for it — most of the 32 checks
encode a bug that actually happened, not one that was imagined.

## Layout

```
Sources/MacarchyKit/      pure logic shared by app + CLI (ported surfaces land here)
Sources/MacarchySettings/ the SwiftUI app — App/ Daemon/ Model/ Views/
Sources/MacarchyCLI/      the `macarchy` CLI, installed to ~/.local/bin/macarchy
Defaults/themes/          the 8 shipped manifests — the reset-to-default baseline
Scripts/build_app.sh      builds, bundles, signs, installs the CLI
Scripts/doctor.sh         32 health assertions — THE GATE
Scripts/test.sh           snapshot, manifest and port round-trip tests
Tests/GhosttyPort/        reference.sh is the original shell, kept for diffing
```

On the machine:
```
~/.config/macarchy-settings/   themes/, settings.env, snapshots/, generated.json
~/.config/themes               SYMLINK into the above (shell still hard-codes it)
~/.local/bin/macarchy          the CLI
~/.local/bin/theme-switch      the 951 lines still to port
~/projects/jankyborders-local  patched JankyBorders fork, now under git
```

Backups: `~/.local/state/macarchy-settings-migration/` holds pre-migration copies
of `themes/`, `bordersrc`, and three `theme-switch` snapshots.

## Build and verify

```sh
./Scripts/build_app.sh debug     # build, bundle, sign, install CLI
./Scripts/run.sh                 # the above, then relaunch
./Scripts/doctor.sh              # THE GATE — must be 0 failed
./Scripts/test.sh                # round-trip tests
```

Signing is ad-hoc, so identity changes each rebuild. Harry should make a
self-signed cert and export `MACARCHY_SIGN_IDENTITY`; the script explains it.

You cannot screenshot the app (no Screen Recording permission for the shell).
To confirm a window rendered, query yabai:
`yabai -m query --windows | grep -i macarchy`.

### Phase 3a — sketchybar items as packages

Independent of 3b. Items become manifests like themes, buildable in the UI and
importable. **All 4 current items are script-backed**, so a package is
declarative properties *plus* a shell script. The trust boundary matters:
a theme is data, a scripted item is code that runs every few seconds. Import
must show the script and require confirmation. See `MIGRATION.md` §3a.

### Phase 4 — hotkeys

Parse `skhdrc` into structured bindings (86 of them, grouped by the section
comments already there), editor UI, then generate `skhdrc`. skhd keeps doing
global key capture. The Shortcuts pane is still a stub.

### Phase 5 — consolidate state

`.current`, `.backgrounds.json`, `.nvim-colorscheme`, `.shell-env` still sit
*beside* the themes rather than inside them, because `theme-switch` owns them.
`float_state.json` → the Rules pane, which is still a stub. This is also when
`~/.config/themes` stops needing to be a symlink.

### Phase 6 — retire

`theme-switch` → the Raycast extension → `~/.config/macarchy` →
`~/.local/state/macarchy` → the symlink. Each only when nothing references it.

## Traps

Every one of these actually happened.

**`theme-switch` regenerates files wholesale.** `write_borders_config()` rewrote
`bordersrc` on every theme switch and silently reverted a completed migration. It
is now a no-op and `doctor` asserts it stays dead. Assume other functions do the
same until you have read them.

**Do not split SketchyBar's chained invocation.** `--bar`, `--load-font` and
`--default` are one call on purpose — separate calls each cost a repaint. A
generator that extracted just the `--bar` group swallowed the font and every
item default with it; the bar still came up and sketchybar still reported
"running". Geometry is applied as a second small call instead.

**`set-wallpaper` is not to be ported.** It encodes desktoppr for the current
Space, direct `Index.plist` rewriting for the others, and osascript fallbacks.
Its failure mode is a grey desktop, which has bitten this machine before. There
is also a `wallpaper_sync` yabai signal in a `macarchy:keep` region doing related
work. Leave all of it alone; the app invokes it.

**`.backgrounds.json` overrides `theme.env`'s `WALLPAPER`.** They already
disagree for most themes. Reading `theme.env` alone shows the wrong image.

**Timestamps need sub-second resolution.** Snapshot ids were second-resolution;
writes debounce ~100ms apart, so captures collided in one directory and
`restore()` destroyed the snapshot it was reading from. Caught only by a test.

**`grep -c` prints `0` and exits `1`.** A `|| echo 0` fallback then emits two
lines and breaks numeric tests. Bit `doctor` in four places.

**zsh does not word-split unquoted expansions.** `for k in $KEYS` iterates once.

**yabai tiles the app's own settings window.** It asks for 860×620 and gets
whatever yabai decides. Adding the app to its own float rules is a sensible
first customer for the Rules pane.

**`sudo yabai --load-sa`** is in a `macarchy:keep` region and relies on a
sudoers entry. The app must never invoke sudo. Restart daemons only via
`launchctl kickstart -k gui/$(id -u)/<label>`.

## Open questions

- **Scripted-item sandboxing.** Reviewing an imported script is a speed bump, not
  a security boundary. Needs a decision before any shared library of items.
- **Colour ownership for SketchyBar.** Theme owns colour and settings owns
  geometry for borders. SketchyBar's bar colour is still a literal in the
  preserved region; it was left alone to keep the Phase 2 gate honest.
- **The macOS 27 Space-switching workaround** (`switch_space_macos27.sh`,
  `skhdrc:55`) is surfaced in the Advanced pane but still unresolved upstream.
